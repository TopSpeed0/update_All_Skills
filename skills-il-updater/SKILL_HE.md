# עדכון סקילים של Skills IL

סקיל של Skills IL מותקן באחד משני מקומות, וכל אחד מהם צריך טיפול אחר:

| איפה | זמין ב־ | מי יכול לעדכן אותו |
|---|---|---|
| **הועלה** דרך Customize ← Skills ← "+" ← Upload a skill | בכל Claude שמחובר לחשבון: claude.ai, האפליקציה, הטלפון | רק המשתמש, על ידי העלאת zip חדש. ל־claude.ai אין API להעלאה |
| **מקומי**, תיקייה ב־`~/.claude/skills` | Claude Code במחשב הזה | הסקיל הזה, אוטומטית |

`npx skills-il update` ו־`gh skill update` מנהלים רק סקילים שהם עצמם התקינו, ולכן סקילים שהועלו וסקילים מקומיים שהועתקו ידנית נשארים מאחור בלי שאף אחד שם לב. הסקיל הזה סוגר את הפער: את העותקים המקומיים הוא מעדכן בעצמו, ובסקילים שהועלו הוא עושה הכול חוץ מהלחיצה האחרונה.

## הוראות

### שלב 1: מריצים את הבדיקה

```bash
python scripts/check_updates.py --check-only
```

הסקריפט מחפש סקילים מותקנים שב־`metadata.json` שלהם כתוב `"author": "skills-il"`:

- **שהועלו:** המטמון של Claude Desktop לסקילים מ־claude.ai (ב־Windows: `%LOCALAPPDATA%\Claude-Data\...\skills-plugin\...\skills`. המקביל ב־macOS, תחת `~/Library/Application Support`, הוא ניסיון בלבד). את התיקייה הזו הסקריפט רק קורא. האפליקציה מסנכרנת אותה מהחשבון, ולכן הוא אף פעם לא כותב אליה.
- **מקומיים:** `~/.claude/skills`, וכל תיקייה שמועברת עם `--skills-dir PATH` (אפשר כמה פעמים).

הריפו של כל סקיל הוא `skills-il/<category>`, לפי השדה `category` ב־`metadata.json` שלו. פלט צפוי: שורה לכל עותק מותקן, ובסוף שורת סיכום:

```
hebrew-document-generator   local      1.6.0 -> 1.8.0   update available
hebrew-document-generator   uploaded   1.6.0 -> 1.8.0   update available
UPDATES: 2  INSTALLED: 0  MANUAL: 1
```

### שלב 2: מעדכנים

```bash
python scripts/check_updates.py --install-local --out ./skill-updates
```

לכל עותק שלא מעודכן, הסקריפט מוריד את תיקיית הסקיל ב־commit האחרון שלה, ומריץ `gh attestation verify` על `SKILL.md` ועל `metadata.json` מול הארגון `skills-il`. האימות מוכיח שהקבצים נבנו ב־workflow השחרור של Skills IL ולא שונו בדרך. קבצים שירדו אף פעם לא מורצים. ואז:

- **עותק מקומי:** התיקייה המאומתת מחליפה את הישנה. קודם התיקייה הישנה עוברת ל־`~/.claude/skill-backups/<name>-v<old>-<time>`, כך שאפשר לבטל את העדכון על ידי החזרה שלה. בלי `--install-local`, עותק מקומי מקבל zip כמו עותק שהועלה.
- **עותק שהועלה:** הסקריפט כותב את הקובץ `<name>-v<version>.zip` לתיקייה שב־`--out`.
- **תיקייה מקושרת** (symlink או junction ב־Windows, כמו שה־CLI של skills-il יוצר): הסקריפט לא נוגע בה. אומרים למשתמש להריץ `npx skills-il update`.

אם חתימה לא מאומתת, שום דבר לא מותקן ולא נבנה zip. אומרים את זה למשתמש. את `--allow-unverified` (רק zip, אף פעם לא התקנה) מציעים רק אם הוא ביקש. הסיבה הנפוצה היא סקיל ששונה אחרי ה־release החתום האחרון שלו, והאפשרות הבטוחה היא לחכות ל־release הבא.

### שלב 3: מעבירים למשתמש את החלק הידני

מדווחים מה עודכן אוטומטית, ואחר כך את קובצי ה־zip. כל zip צריך את השלבים האלה, כי אף סוכן לא יכול להעלות ל־claude.ai בשם המשתמש:

1. סרגל הצד ← Customize ← Skills.
2. פותחים את הסקיל הישן ← "..." ← Delete, כדי שלא יהיו פעילים שני סקילים באותו שם.
3. "+" ← Create skill ← Upload a skill ← בוחרים את קובץ ה־zip.
4. מוודאים שהסקיל החדש מופעל, ואז סוגרים לגמרי את אפליקציית הדסקטופ (Quit) ופותחים מחדש.

### שלב 4 (רשות): הופכים את זה לשגרה שבועית

מתזמנים את `python scripts/check_updates.py --install-local --out <folder>` פעם בשבוע, דרך המתזמן של הסוכן או של מערכת ההפעלה (cron, Task Scheduler). קוראים את השורה האחרונה. מודיעים למשתמש רק כש־`MANUAL` הוא לא 0, ומזכירים בשורה אחת עדכונים שבוצעו (`INSTALLED`). שבוע בלי שום דבר לעשות עובר בשקט.

## דוגמאות

### דוגמה 1: בדיקת מצב
המשתמש אומר: "הסקילים של Skills IL שלי מעודכנים?"
פעולות:
1. מריצים `python scripts/check_updates.py --check-only`.
2. מציגים את הטבלה כרשימה קצרה, מחולקת למקומיים ולכאלה שהועלו.
תוצאה: "ל־3 סקילים שהועלו יש עדכון. העותקים המקומיים מעודכנים."

### דוגמה 2: לעדכן הכול
המשתמש אומר: "תעדכן את הסקילים שלי."
פעולות:
1. מריצים `python scripts/check_updates.py --install-local --out ./skill-updates`.
2. מדווחים מה הוחלף מקומית, עם נתיבי הגיבוי.
3. מציגים כל zip עם תוצאת האימות שלו, ואת ארבעת שלבי ההעלאה.
תוצאה: הסקילים המקומיים מעודכנים, וב־`./skill-updates` יש קובצי zip מאומתים לסקילים שהועלו.

## פתרון בעיות

### שגיאה: "No installed skills by "skills-il" found"
**סיבה:** הסקילים נמצאים במקום שהסקריפט לא בודק, או שהם ממפרסם אחר.
**פתרון:** מעבירים את התיקייה עם `--skills-dir`, או משתמשים ב־`--author` למפרסם אחר שהריפו שלו בנוי באותו מבנה `<org>/<category>/<skill>` (ומגדירים גם `--owner`).

### שגיאה: "lookup failed: HTTP Error 403"
**סיבה:** המגבלה של GitHub לבקשות אנונימיות (60 בשעה).
**פתרון:** מתחברים עם `gh auth login`, או מגדירים `GITHUB_TOKEN`. הסקריפט מזהה את שניהם לבד.

### סטטוס: "not installed: signature not verified" או "zip withheld"
**סיבה:** קבצי הסקיל השתנו אחרי ה־release החתום האחרון שלו, או ש־`gh` לא הצליח להגיע ל־Sigstore.
**פתרון:** מנסים שוב מאוחר יותר. אם זה נמשך, מדווחים לריפו של הסקיל. הגרסה המותקנת נשארת כמו שהיא.

### ביטול עדכון מקומי
מחזירים את התיקייה מ־`~/.claude/skill-backups/` אל `~/.claude/skills/<name>`. קודם מוחקים את החדשה או משנים את השם שלה.

### סטטוס: "gh CLI not found"
**סיבה:** GitHub CLI לא מותקן, ולכן אי אפשר לבדוק חתימות.
**פתרון:** מתקינים gh מ־https://cli.github.com ומריצים `gh auth login`.
