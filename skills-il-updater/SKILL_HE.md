# עדכון סקילים של Skills IL

פקודה אחת שומרת על כל הסקילים של Skills IL במחשב מעודכנים:

```bash
python scripts/check_updates.py --update
```

המשתמש צריך לזכור רק שני דברים:

1. **לתזמן** את הפקודה פעם בשבוע, אם הוא רוצה שהיא תרוץ לבד (שלב 3).
2. **להעלות את קובצי ה־zip** מ־`~/skill-updates` לסקילים שאמורים לשבת ב־claude.ai (שלב 2). ל־claude.ai אין API להעלאה, ולכן רק השלב הזה נשאר ידני.

כל השאר אוטומטי.

## איפה סקילים יושבים, ומה קורה לכל אחד

| הותקן כ־ | איך מוצאים אותו | מה `--update` עושה | מה המשתמש עושה |
|---|---|---|---|
| **CLI**: `npx skills-il add -g` | `~/.agents/.skill-lock.json` | מריץ `npx skills-il update`, ואחר כך מתקין מחדש (רק את הסקיל הזה) כל סקיל שה־update דילג עליו | כלום |
| **עותק מקומי**: תיקייה ב־`~/.claude/skills` עם `metadata.json` (נפרס מה־zip של האתר, שוכפל, הועתק) | `metadata.json` עם `"author": "skills-il"` | מוריד את הגרסה האחרונה, מאמת את חתימת ה־Sigstore, מגבה את התיקייה הישנה ל־`~/.claude/skill-backups` ומחליף אותה | כלום |
| **הועלה** ל־claude.ai או ל־Claude Desktop | המטמון של אפליקציית הדסקטופ (קריאה בלבד) | מוריד, מאמת וכותב `<name>-v<version>.zip` ל־`~/skill-updates` | להעלות את ה־zip |
| **תיקייה מקושרת** (symlink או junction ב־Windows) | `~/.claude/skills` | לא נוגע בה | כלום |

כללים שתמיד מתקיימים:

- שום דבר לא מותקן ולא נארז ב־zip אם החתימה שלו לא אומתה.
- קבצים שירדו אף פעם לא מורצים.
- את המטמון של אפליקציית הדסקטופ הסקיל רק קורא, אף פעם לא כותב אליו.
- תיקיות של ה־CLI משתנות רק על ידי ה־CLI עצמו.

## בעיות ידועות שהסקיל עוקף

הבעיות האלה עלו בבדיקות אמיתיות ב־Windows 11, עם התקנות של ה־CLI של skills-il והעלאות ל־claude.ai.

| בעיה | התוצאה | מה הסקיל עושה |
|---|---|---|
| אף כלי לא מעדכן סקילים שהועלו | `npx skills-il update` ו־`gh skill update` מנהלים רק את ההתקנות של עצמם. סקילים שהועלו מתיישנים בשקט | משווה כל אחד ל־GitHub ובונה zip מאומת |
| ה־CLI רושם `skillFolderHash` ריק כשהפניות שלו ל־GitHub נכשלות בזמן ההתקנה (מספיק `GITHUB_TOKEN` שפג תוקפו), ולא מזהיר | `npx skills-il check` ו־`update` מחזירים "No version hash available" ולא מעדכנים את הסקיל הזה לעולם | מזהה שהוא ישן לפי commits מאז ההתקנה ולפי תוכן ה־`SKILL.md`, ומתקין מחדש רק את הסקיל הזה, וכך נרשם hash חדש |
| התיקון שה־CLI מציע הוא `npx skills add <repo> -g -y` | חבילה לא נכונה (`skills` במקום `skills-il`), ובלי `--skill` היא מתקינה את כל הסקילים בריפו | לא מריץ אותה. מתקין מחדש עם `--skill <name>` |
| הרצת npx עם טוקן לא תקין יוצרת את ה־hash הריק | הרצת ה־CLI עם טוקן שפג יוצרת את הבעיה עצמה | בודק את הטוקן קודם. npx רץ רק עם טוקן שעובד, ואחרת מדלגים עליו עם הודעה |
| ה־CLI לא מעתיק את `metadata.json` | הגרסה המותקנת לא שמורה על הדיסק | קורא את הגרסה מ־`CHANGELOG.md` |
| הקבצים מגיעים עם סיומות שורה CRLF (בגלל `autocrlf` של git) | השוואה בייט־בייט אומרת שכל קובץ השתנה | משווה בלי להתחשב בסיומות השורה |
| אפליקציית הדסקטופ שומרת את ה־`GITHUB_TOKEN` שהייתה לה בזמן שעלתה | אחרי החלפת טוקן, כלים שרצים מהאפליקציה משתמשים בישן עד שמפעילים אותה מחדש | משתמש ב־`GITHUB_TOKEN` או ב־`GH_TOKEN`, ואם אין אז ב־`gh auth token`, ומדווח על טוקן לא תקין במקום להיכשל |
| ב־Windows קישורים הם לרוב junctions, ו־`os.path.islink` לא מזהה אותם | תיקייה מקושרת עלולה להיראות כמו עותק רגיל | מזהה גם junctions ולא נוגע בהן |
| אותו סקיל יכול להיות גם מועלה וגם מקומי | ב־Claude Code יופיעו אז שני סקילים באותו שם | מדווח על כל עותק בנפרד. כדאי להשאיר עותק אחד לכל סקיל |
| ה־zip מהאתר של Skills IL נוצר ברגע הלחיצה ואין עליו חתימה | אין דרך לדעת שהוא תואם ל־release החתום | אורז ב־zip רק קבצים שה־attestation שלהם אומת |

## הוראות

### שלב 1: מריצים

```bash
python scripts/check_updates.py --update
```

עם `--check-only` רואים את המצב בלי לשנות כלום. כל שורה מציגה את הסקיל, איך הוא מותקן (`cli`, `local`, `uploaded`), את הגרסה המותקנת והאחרונה, ומה קרה. השורה האחרונה מסכמת:

```
UPDATES: 2  INSTALLED: 1  MANUAL: 1  BLOCKED: 0
```

- `INSTALLED`: עודכנו אוטומטית.
- `MANUAL`: קובצי zip שמחכים ב־`~/skill-updates`.
- `BLOCKED`: לא היה אפשר לעדכן. שורות ה־`NOTE:` מסבירות למה (אין npx, טוקן לא תקין, חתימה לא אומתה).

אפשרויות: `--out DIR` לתיקיית zip אחרת, `--skills-dir DIR` לתיקיות סקילים נוספות, `--json` לפלט שמחשב יכול לקרוא. `--allow-unverified` בונה zip גם כשהאימות נכשל. לא משתמשים בו אלא אם המשתמש ביקש במפורש.

### שלב 2: מעבירים למשתמש את קובצי ה־zip

אם `MANUAL` הוא לא 0, אומרים למשתמש שהקבצים נמצאים ב־`~/skill-updates` (בשורה `ZIPS TO UPLOAD:` מופיע הנתיב המלא). לכל קובץ zip:

1. סרגל הצד ← Customize ← Skills.
2. פותחים את הסקיל הישן ← "..." ← Delete, כדי שלא יהיו פעילים שני סקילים באותו שם.
3. "+" ← Create skill ← Upload a skill ← בוחרים את קובץ ה־zip.
4. מוודאים שהוא מופעל, ואז סוגרים לגמרי את אפליקציית הדסקטופ (Quit) ופותחים מחדש.

את הפריטים ב־`BLOCKED` לא מציגים כמשימות. מסבירים פעם אחת מה הסיבה.

### שלב 3: מתזמנים (רשות)

מריצים את אותה פקודה פעם בשבוע. בוחרים אחת:

- **המתזמן של הסוכן**, למשל משימה מתוזמנת עם ההנחיה "הרץ `python <path>/scripts/check_updates.py --update` ותודיע לי רק אם `MANUAL` או `BLOCKED` שונים מ־0".
- **Windows**: `schtasks /Create /SC WEEKLY /D SUN /ST 09:00 /TN skills-il-updater /TR "python <path>\scripts\check_updates.py --update"`
- **macOS/Linux** (cron): `0 9 * * 0 python3 <path>/scripts/check_updates.py --update`

התזמון צריך התחברות תקינה ל־GitHub (`gh auth login`, או `GITHUB_TOKEN` במשתני הסביבה של המשתמש), כדי ש־npx לעולם לא ירוץ עם טוקן שפג.

## דוגמאות

### דוגמה 1: "הסקילים שלי מעודכנים?"
מריצים `python scripts/check_updates.py --check-only` ומסכמים ברשימה קצרה אחת.

### דוגמה 2: "תעדכן את הסקילים שלי"
מריצים `python scripts/check_updates.py --update`. מדווחים בשורה אחת מה עודכן אוטומטית, ואם `MANUAL` גדול מ־0, את תיקיית ה־zip ואת ארבעת שלבי ההעלאה.

### דוגמה 3: "תגדיר עדכון שבועי"
מסבירים את שני הדברים שצריך לזכור, יוצרים את התזמון (שלב 3) ומריצים פעם אחת עכשיו.

## פתרון בעיות

### `NOTE: npx not found`
Node.js לא מותקן, ולכן אי אפשר לעדכן התקנות CLI. מתקינים Node.js LTS (למשל `winget install OpenJS.NodeJS.LTS`) ומריצים שוב.

### `NOTE: GITHUB_TOKEN missing or invalid`
מריצים `gh auth login`, או מחדשים את הטוקן ומגדירים אותו שוב. אחר כך מפעילים מחדש את אפליקציית הדסקטופ, כי היא שומרת את הטוקן שהיה לה כשעלתה.

### `still outdated after re-install`
הקבצים האחרונים השתנו אחרי ה־release האחרון, או ש־GitHub לא היה זמין לרגע. מריצים שוב מאוחר יותר.

### `not installed: signature not verified` או `zip withheld`
הסקיל השתנה אחרי ה־release החתום האחרון שלו, או ש־Sigstore לא היה זמין. הגרסה המותקנת נשארת כמו שהיא. מחכים ל־release הבא.

### ביטול עדכון מקומי
מחזירים את התיקייה מ־`~/.claude/skill-backups/` אל `~/.claude/skills/<name>`. קודם מוחקים את החדשה או משנים את השם שלה.

### `No installed skills by "skills-il" found`
מעבירים תיקיות נוספות עם `--skills-dir`, או משתמשים ב־`--author` וב־`--owner` למפרסם אחר שהריפו שלו בנוי באותו מבנה `<org>/<category>/<skill>`.
